## Submission order

Don't apply to one — stack-apply for portfolio effect:

1. **Week 0–2 after arrival**: OCF microgrant (#1) — fastest, lowest bar
2. **Week 2–4**: Anchor Taiwan (#3) — Gold Card holder window
3. **Week 4–8**: g0v grant (#2) — when round opens
4. **Ongoing**: moda RFPs (#4), hackathons (#5) — opportunistically

If 2 of 5 hit, you're at NT$200k–700k in 6 months — enough to fund through v1.0.

## What every reviewer wants to see

The five proposals share these core elements. Don't mix and match — each section should be tailored to the specific program's grading rubric.

- **Concrete problem statement** (not "Taiwan needs better UX")
- **Proof project exists and works** (live URL + GitHub)
- **Specific deliverables tied to budget line items**
- **Sustainability plan post-grant**
- **Honest scope boundaries** (don't oversell)

## Honesty principle

These drafts pre-fill what's true based on the current state of the repo. Do not add achievements or numbers that aren't real. Reviewers cross-check — fabricating a "500 weekly downloads" claim when npm shows 0 will get you blacklisted from future rounds.

If a number is aspirational (e.g. "expect 500 weekly downloads by month 3"), say so explicitly.

## Maintenance

When a proposal is submitted, mark it in [`SUBMISSIONS.md`](./SUBMISSIONS.md) with date, version, and outcome. This builds a track record for follow-on applications.
